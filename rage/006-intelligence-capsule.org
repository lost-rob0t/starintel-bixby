** Design
- Root :: =capsules/starintel-intelligence/= with one real Bixby capsule and no Operations models/scopes.
- Capsule identity :: development ID uses =playground.starIntelIntelligence= until the operator supplies the registered Developer Center namespace; target =bixby-mobile-en-US= and =format (3)=.
- Models :: primitives for query/IDs/names/document scalar fields; structures for =PersonMatch=, =PersonProfile=, =PersonSearchResult=, =DocumentHit=, =DocumentSearchResult=; actions =ResolvePerson= and =SearchDocuments=.
- Person resolution result :: normalized Bixby result carries zero/one/many ranked matches plus a selected profile only when backend resolution is unambiguous. Same-name ambiguity is represented and presented for user selection rather than first-result choice.
- Context :: training continuations target the same person/document goal and rely on the selected =PersonMatch=/stable =PersonId= from the prior plan. Cold-start follow-up has no person value and must prompt/elicit rather than manufacture identity.
- Documents :: =SearchDocuments= accepts query, optional dtype, optional bounded limit, and optional selected =PersonId=. Spoken/default limit contract is 5; JS endpoint adapter clamps a user-supplied limit to the capsule's bounded maximum before issuing the public gateway request.
- Endpoint adapter :: local JS reads a Developer Center configuration key for the public gateway origin, requires HTTPS, rejects private/internal hosts, calls only tentative =/v1/bixby/person/resolve= and =/v1/bixby/documents/search= paths owned by epic #1, and returns normalized Bixby-facing objects. No StarIntel service credentials exist here.
- OAuth :: do not create a fabricated =authorization.bxb=. Add a static integration manifest documenting required Intelligence scopes and a validator that will require real authorization once canonical public OAuth endpoints are supplied. Issue #8 remains the freeze gate for the final auth/HTTP contract.
- Views :: person search provides explicit ambiguity list/details; document search renders bounded results and uses =attribution-link= for =DocumentUrl=.
