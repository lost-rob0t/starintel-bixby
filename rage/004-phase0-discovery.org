** Design
- Dedicated artifact :: =docs/architecture.md=.
- Two-capsule authority split remains valid: Intelligence read/search only; Operations receives narrowly additional target/Auto-Dig scopes.
- Local JS endpoint adapters are preferred where Developer Center dynamic configuration/OAuth/error normalization is needed; they call the public gateway and never carry StarIntel upstream credentials.
- Person/document/target/run concepts are Bixby presentation/wire contracts only.
- Person/run follow-ups use continuation context but send stable IDs back to the gateway for revalidation.
- Documents use attribution links by default; one server-side configured-origin link builder owns public URL generation after infra proves the origin/route.
- Mutations use prepare -> transactional confirmation -> commit -> receipt. Gateway reauthorizes/revalidates at commit; confirmation is not itself authority.
- Target actor/type values resolve against canonical metadata; arbitrary raw actor/RMQ values are rejected.
- Auto-Dig contract may model desired operations, but integration stays capability-gated until owning typed commands exist.
- Frozen =/v1/bixby/...= fixtures precede infra implementation.

** Adversarial review

- Direct capsule-to-internal-StarIntel :: rejected; leaks/duplicates internal auth/routing and bypasses public boundary controls.
- Hard-coded =quasar.starintel.actor= :: rejected; current infra only shows this as non-deployed example intent.
- Browser/Playwright/DB/RabbitMQ Auto-Dig control :: rejected; none owns canonical durable run lifecycle.
- Raw actor name from voice :: rejected; actor docs prove raw names can map to internal/external Rabbit routes.
- Capsule-side idempotency token as sole dedupe :: rejected; network retry correctness belongs at owning target/run mutation boundary.
- Auto-open browser for every document :: rejected; current Samsung punch-out guidance prefers explicit attribution links.
- Visual interpretation of "this person" :: rejected for v1; continuation is conversational context only.
- Threat focus for next slices :: ambiguous identity, scope escalation between capsules, stale/missing context, mutation replay, raw internal URL leakage, capability absence, timeout amplification, cross-user run access, and confirmation bypass.
